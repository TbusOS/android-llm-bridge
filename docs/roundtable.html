Several models, one thread, one bug. 几个模型，一个对话，查同一个 bug。

The plan for the web UI: the main brain, a log watcher, a model on the board and the analysis tools sit in one conversation with you. Each says what it saw from where it sits, and the evidence collects in a panel beside the thread, every item pointing back at the raw data. 网页界面的规划：主脑、日志哨兵、板上模型和分析工具，跟你坐在同一个对话里。每一位说的是它在自己那个位置上看到的东西；证据汇总在对话旁边的面板里，每一条都能指回原始数据。

This is a plan, not a feature. Today the web assistant is one model in one conversation. The window below is a concept sketch of what several models in one thread could look like; the conversation is written by hand.这是规划，不是现有功能。现在的网页助手是一个模型、一个对话。下面的窗口是概念示意，画的是几个模型同在一个对话里大概什么样；对话内容是手写的。

The seats每个位置

Each one sees something the others cannot.每一位看到的，别的位置看不到。

The point of several models is not more opinions. It is that they sit in different places: next to the code, next to the log stream, on the board, on the profiler.放几个模型进来，不是为了多几份意见，而是因为它们坐的地方不一样：挨着代码、守着日志流、在板子上、在分析工具旁边。

Main brain主脑

Your coding agent on the build server. It already drives boards over MCP and the CLI: it edits, builds, flashes and reads logs.编译机上你的编程助手。它现在已经能经 MCP 和命令行调板子：改代码、编译、烧录、读日志。

Log watcher日志哨兵

A small local model that reads the whole stream. The local-model backend exists today; watching by itself and reporting into a shared thread does not.读完整条日志流的本地小模型。接本地模型的后端现在就有；自己盯日志、往共同的对话里汇报，还没有。

Several models, one thread几个模型，一个对话

  • Each message says which model wrote it and where that model runs每条消息写明是哪个模型说的、它跑在哪
  • Evidence is a shared list of marks that point back at raw logs and pictures证据是一张大家共用的标记表，每个标记指回原始日志或图
  • Analysis tools post views into the thread, not only text分析工具往对话里发的是视图，不只是文字
  • You still decide: anything that changes the board waits for your yes拍板的还是你：会改板子的动作，等你点头
