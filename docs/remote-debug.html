The brain at site A. The board at site B. 主脑在 A 地，板子在 B 地。

The model, the source tree and the alb hub stay on a machine at one site. The board stays on a bench PC somewhere else: another building, a lab, a customer's desk. The bench agent opens every connection outwards, so site B opens no inbound port and nobody ships the board. 模型、源码树和 alb hub 留在一个地方的机器上。板子留在另一个地方的台架电脑上：另一栋楼、实验室、客户的桌子上都行。每条连接都由台架 agent 往外发起，B 地不用开任何入站端口，板子也不用寄来寄去。

  • shipped已实现The agent dials the hub for signaling and for every data channel; the hub never connects back. adb, the serial console, fastboot, Qualcomm EDL and vendor tools all ride these connections.信令和每一条数据通道都由 agent 连向 hub，hub 从不反过来连。adb、串口、fastboot、高通 9008、厂商工具都走这些连接。
  • not yet measured还没实测The bench used so far sits in one office network on ws://. The wss:// path through a reverse proxy, and how a slow or distant link feels, have not been tried on a real bench.目前用过的真台架和 hub 在同一个办公网里，走的是 ws://。经反向代理的 wss://，以及又远又慢的链路上用起来怎么样，还没有在真台架上试过。
How the two sites meet两地怎么连上

One direction only: the bench calls home.方向只有一个：台架往回拨。

The one requirement is that the bench PC can open a TCP connection to the hub's address and port. Everything after that, in both directions, travels inside connections the agent opened.只有一个要求：台架电脑能连到 hub 的地址和端口。之后两个方向的所有数据，都走在 agent 自己开出来的连接里。

  1. The bench agent starts and dials the hub's address. Site B's firewall only sees an outgoing connection.台架 agent 启动，拨 hub 的地址。B 地的防火墙看到的只是一条出站连接。
  2. The hub checks the token. Each adb, serial or flash channel after this is another connection the agent opens.hub 核对令牌。之后每一条 adb、串口、烧录通道，都是 agent 再开出来的一条连接。
  3. At site A the agent runs alb flash write. The image crosses the link once and the bench agent flashes it next to the board.A 地的 AI 助手跑 alb flash write。镜像过一次链路，台架 agent 在板子旁边把它烧进去。
  4. UART bytes and logs flow back into the workspace at site A, where the model reads them.串口字节和日志流回 A 地的工作区，模型在那边读。

Pick a setup选一种接法

Same desk or another country: only hub_url changes.同一张桌子还是另一个国家，改的只有 hub_url。

hub_url is one line in the bench PC's agent.conf. What differs between setups is what you put in front of the hub.hub_url 是台架电脑 agent.conf 里的一行。各种接法的区别，在于 hub 前面放什么。

Same LAN同一个局域网

ws://<hub-ip>:8765/agent/connect
Nothing to set up. This is the setup used on a real bench so far.不用额外配置。目前真台架用的就是这种。

Different subnets, routed不同网段，有路由

ws://<hub-ip>:8765/agent/connect
Office VLANs or two buildings: let the bench reach the hub's port through the firewall.办公室的不同 VLAN、两栋楼之间：防火墙放行台架到 hub 那个端口。

Two sites over a VPN两地，走 VPN recommended推荐

ws://<hub-vpn-ip>:8765/agent/connect
WireGuard, Tailscale or the company VPN on both machines. The hub stays off the public internet.两台机器都接进 WireGuard、Tailscale 或公司 VPN。hub 不暴露在公网上。

Two sites, reverse proxy with TLS两地，带 TLS 的反向代理

wss://hub.example.com/agent/connect
A proxy in front of the hub, with a login on everything except the two agent endpoints. The runbook has an nginx example; it has not been run on a real proxy yet.hub 前面放一个代理，除了 agent 用的两个地址以外都要登录。手册里有一份 nginx 示例，这份示例还没在真的代理上跑过。

Two sites, port relay两地，端口中转

ws://<relay>:<port>/agent/connect
frp and similar forward to the hub's port. The same login rule applies as for the proxy.frp 这类工具把连接转到 hub 的端口。登录的要求和反向代理一样。
Do not publish port 8765 as it is. Only the two agent endpoints check a token. The web UI and the rest of the HTTP API have no login, so anyone who can reach the port can run commands on your boards and flash them. Across the internet, use a VPN or a proxy that makes people log in.不要把 8765 端口直接放到公网上。只有 agent 用的两个地址会核对令牌；网页和其余的 HTTP 接口没有登录，谁能连到这个端口，谁就能在你的板子上跑命令、烧录。跨公网时用 VPN，或者用要求登录的代理。
Set it up怎么配

One file at each site.两边各改一个文件。

site A · Linux · the hubA 地 · Linux · hub
$ cd deploy/hub
$ cp hub.env.example hub.env
# in hub.env: the shared token
ALB_AGENT_TOKEN=<a-long-random-string>
$ ./run-hub.sh
site B · Windows · agent.confB 地 · Windows · agent.conf
# copy clients/windows-agent/ to the bench PC
hub_url=ws://<hub-vpn-ip>:8765/agent/connect
token=<the-same-string>
name=bench-01
# then double-click run-agent.bat

Check it from the bench在台架这边自查

The agent serves a status page on the bench PC itself, at http://127.0.0.1:8731: connected or not, and the last error. On the hub, alb devices listing the board means the data channels made it too.agent 在台架电脑本机开一个状态页 http://127.0.0.1:8731：连没连上、最近一次报错是什么。hub 这边 alb devices 能列出板子，说明数据通道也通了。
