A big model to think. Small models to watch. 大模型拿主意，小模型盯日志。

One boot prints far more than a frontier model should read. alb is built so each role can use the model that fits it: the main brain plans and patches, a small model sits next to the log stream, and what passes between them is a finding and a pointer to the raw lines, not the whole log. 板子启动一次打印的东西，远比一个大模型值得读的多。alb 的设计是让每个角色用合适的模型：主脑负责想和改，小模型守在日志旁边，两边之间传的是结论和原文位置，不是整份日志。

  • shipped已实现The main brain (Claude Code, Codex, Cursor or your own model) drives the board over MCP or the CLI, and every log lands in a workspace on disk.主脑（Claude Code、Codex、Cursor 或你自己的模型）经 MCP 或命令行调板子，日志全部落在磁盘上的工作区里。
  • shipped已实现The hub's own assistant and alb chat run on a local model (Ollama, any OpenAI-compatible server) or on Anthropic, with the same board tools.hub 自带的助手和 alb chat 可以跑在本地模型上（Ollama、任何 OpenAI 兼容的服务），也可以接 Anthropic，用的是同一套板子工具。
  • planned规划中A small model that watches the stream by itself and hands findings to the main brain.小模型自己盯着日志流，把结论交给主脑。
  • design only只有设计A model that runs on the board itself.直接跑在板子上的模型。
The hand-off怎么交接

The small model reads everything. The big model reads three lines.小模型全量读，大模型只读那几行。

The left column exists today: alb records UART, logcat and dmesg in full. The middle step is the plan: a small model next to the stream that flags what matters, so the main brain pays for findings instead of raw logs and can still open the original lines to check.左边那一列现在就有：alb 把串口、logcat、dmesg 全量录下来。中间那一步是规划：一个守在日志旁边的小模型，把要紧的标出来。主脑花 token 读的是结论，不是原始日志；想核对时，原文随时能打开。

Where the small model runs小模型放在哪

Three places for a small model, each closer to the board.小模型有三个位置，一个比一个靠近板子。

The closer it sits, the less has to cross the network and the more it can see by itself. The first place works today; the other two are the plan.放得越近，要过网络的东西越少，它自己能看到的越多。第一个位置现在就能用，后两个是规划。

A local model next to the hubhub 旁边的本地模型

Today: the hub's assistant and alb chat run on Ollama or any OpenAI-compatible local server and call 35 board tools. An MCP client can also pass one question to the local model with alb_playground_chat. Planned: it reads new logs in the workspace by itself.现在：hub 的助手和 alb chat 可以跑在 Ollama 或任何 OpenAI 兼容的本地服务上，能调 35 个板子工具。MCP 客户端还可以用 alb_playground_chat 把一个问题交给本地模型。规划：让它自己读工作区里新落下的日志。

What works today现在能用的

Two models on one board, set up in two commands.两个模型用同一块板，两条命令配好。

The automatic hand-off is not built, but both seats are. Your coding agent connects over MCP; a local model runs the hub's own assistant, in a terminal or in the web UI.自动交接还没做，但两个位置都已经有了。编程助手经 MCP 接进来；本地模型跑 hub 自带的助手，终端里和网页里都能用。

main brain · your coding agent主脑 · 你的编程助手
# in your android-llm-bridge checkout
$ claude mcp add alb -- uv run --project "$PWD" alb-mcp
# or
$ codex mcp add alb -- uv run --project "$PWD" alb-mcp
local model · the hub's assistant本地模型 · hub 自带的助手
$ export ALB_OLLAMA_URL=http://<llm-host>:11434
$ export ALB_OLLAMA_MODEL=<model>
$ uv run alb chat      # in a terminal, with the board tools
$ uv run alb-api       # web UI and its assistant at /app

Backends: Ollama, OpenAI-compatible, Anthropic (src/alb/agent/backends/). Settings: configuration.md, llm-integration.md.后端：Ollama、OpenAI 兼容接口、Anthropic（src/alb/agent/backends/）。配置项见 configuration.md 和 llm-integration.md。
