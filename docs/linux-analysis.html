If it runs a Linux kernel, from a dev board to a big server. 跑 Linux 内核的都能查：从开发板到大型服务器。

The next main line of work for alb: collect with the tools Linux already has, such as profilers, the scheduler's tracepoints, leak detectors, eBPF and ftrace, network tools and plain logs; let a model read the result; and draw the answer in the browser. Where the CPU time goes, which thread is waiting on which lock, where the memory went, which source line the crash is on. 这是 alb 接下来的主力方向：用 Linux 自己已经有的工具采数据（性能分析、调度器跟踪点、内存泄漏检测、eBPF 和 ftrace、网络工具，还有日志本身），交给模型读，再在网页上把答案画出来。CPU 时间花在哪、哪个线程在等哪把锁、内存去了哪、崩在源码的哪一行。

Everything on this page is a plan. None of it is in the code yet. The pictures below are concept sketches: the shapes, names and conclusions are invented to show what a view would look like, and none of them is a measurement.这一页全部是规划。代码里还没有。下面的画面是概念示意：图形、名字和结论都是为了说明「这种视图长什么样」编出来的，没有一处是真实测量结果。

Which lock is everyone on?线程都堵在哪把锁？

sketch示意who waits for whom谁在等谁
worker-aworker-bworker-cworker-d

The workers are not short of CPU: they are all parked on cache_lock, and the flusher thread holds it across a disk write. The bottleneck is how much this one lock covers.工作线程不是缺 CPU，是都停在 cache_lock 上；刷盘线程拿着它去写磁盘。瓶颈在这把锁管得太宽。

Where did the memory go?内存去哪了？

sketch示意growth over time, and who allocated it占用随时间的变化，和是谁分配的

Usage climbs in steps and never comes back down. Nearly all of what is still held was allocated in session_open(); its error path returns without freeing the buffer.占用一级一级往上走，不回落。还没释放的内存几乎都是 session_open() 里分配的：它的出错路径没有释放缓冲区就返回了。

Which line crashed?崩在哪一行？

sketch示意from the PC pointer to the source line从 PC 指针到源码行

drivers/demo/panel.cstatic int panel_demo_resume(struct device *dev) struct panel *p = dev_get_drvdata(dev); gpiod_set_value(p->reset, 1); return 0;
The PC is on the line that drives the reset pin, and p is NULL there: resume ran before probe had stored the driver data. The symbols were already on the build server, next to the hub.PC 落在拉复位脚的那一行，这里的 p 是空指针：resume 跑在了 probe 存好驱动数据之前。符号文件本来就在编译机上，挨着 hub。

The first hop is clean. Retransmits only show up between the switch and the peer, so start with that link's negotiated speed and its error counters.第一段是干净的，重传只出现在交换机到对端之间。先查那一段协商出来的速率和错误计数。

The first half holds only routine lines. A new kind of timeout starts in the middle, and the watchdog warnings follow it, never the other way round. Open any cell to read the lines behind it.前半段只有常规打印。从中间开始冒出一类以前没有的超时，看门狗告警总是跟在它后面，没有反过来的。点开任何一格都能看到背后的原文。

Not only embedded不只是嵌入式

The same kernel, three sizes of machine.同一个内核，三种大小的机器。

The collectors come with Linux, so the same questions can be asked of a board on a bench, a PC and a server with many cores. What changes is how alb reaches the machine and which question hurts most.这些采集工具是 Linux 自带的，所以台架上的板子、PC、多核服务器，问的是同一批问题。不同的是 alb 怎么连到这台机器，以及哪个问题最疼。

Dev boards and embedded devices开发板和嵌入式设备

Boot time, suspend and resume, a driver that hogs a core, a crash with only a PC value on the serial console. Reached the way alb reaches boards today: adb, ssh or UART, through the bench agent.启动时间、休眠唤醒、把一个核占满的驱动、串口上只留下一个 PC 值的崩溃。连法和 alb 现在连板子一样：adb、ssh 或串口，经台架 agent。

planned规划中

PCs and workstationsPC 和工作站

A desktop that stutters, a build that is slower than it should be, a peripheral driver under test. Reached over ssh.偶尔卡一下的桌面、慢得不正常的编译、正在调的外设驱动。走 ssh 连。

planned规划中

Large servers大型服务器

Concurrency problems, finding the system's bottleneck, naming the processes and threads responsible, and turning piles of logs into something you can look at. Reached over ssh; a BMC serial console is on the roadmap.并发问题、找系统瓶颈、定位到是哪些进程和线程、把成堆的日志变成能看的图。走 ssh 连；BMC 网络串口在路线图上。

What goes in the box工具箱里放什么

Eight families of tools, each with a view.八类工具，每一类配一种视图。

alb will not rewrite these tools. The plan is to start them on the target, bring the raw data back to the workspace, and add the two parts they lack: a model that reads the result, and a view that shows it.alb 不会重写这些工具。计划是在目标机上把它们跑起来，把原始数据收回工作区，再补上它们没有的两样：读结果的模型，和把结果画出来的视图。
