上一次开机的内核崩溃是怎么回事?把前后的日志也看一下。

alb_diag_pstore device=board-a0.4 s
参数 
{
  "device": "board-a"
}
输出 · 4 行
Unable to handle kernel NULL pointer dereference at virtual address 0000000000000008
pc : sensors_poll+0x4c/0x1a0
lr : sensors_poll+0x30/0x1a0
Kernel panic - not syncing: Oops: Fatal exception
alb_log_search pattern=sensors_poll|iio:device01.1 sdmesg 9 · logcat 31 · timeline 09:30–09:32
alb_shell "ls -lZ /dev/iio:device0"只读 · 0.2 scrw-rw---- system system u:object_r:iio_device:s0
qwen2.5:7b · 本机 · 6.1 s

崩溃点在传感器驱动的 sensors_poll+0x4c,读的地址是 0x8。这是空指针再加 8 字节偏移:结构体指针还没建好就被用了。

就在它之前,14 条 SELinux 拒绝让 hal_sensors_default 读不了 iio:device0,HAL 也打出 “open failed: Permission denied”。推测顺序:打开失败 → 驱动私有数据没建 → poll 用到空指针。这个顺序是按时间推出来的,还没验证。
